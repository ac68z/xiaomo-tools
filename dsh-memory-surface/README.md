# dsh-memory-surface

给 DeepSeek Harness（DSH）用的**记忆浮现**插件。

解决一个很具体的问题：**AI 明明写过记忆，却从来不去看**——于是表现得像「我没做过」。

它做的事情很朴素：在每一轮开始、模型还没开口之前，先替它去翻一遍本会话的旧记忆，把最像的那两三条**带着来源**摆到它面前。

不靠模型自觉，靠钩子。不靠它想起来，靠流程。

---

## 它怎么运行

五个步骤，全部在本机：

1. **钩子**：宿主在组装一轮上下文之前有个 `agent/pre-step` 阶段，插件挂在这里，拿到刚进来的那句用户输入。
2. **问服务**：把这句话发给本机一个常驻的向量检索服务（默认 `http://127.0.0.1:8799`），服务负责把每条记忆提前算成向量并缓存。
3. **比相似度**：算余弦相似度，超过阈值才算命中（默认 `0.52`）。低了会乱捞，高了会漏。
4. **注入上下文**：命中的取前 2～3 条，作为带来源（日期 + 标题）的提示折进本轮上下文，在会话里显示成一段「记忆浮现」提醒。
5. **去重**：同一句话只浮现一次（文本指纹），避免同一段旧事反复刷屏。

三条硬规矩：

- **只查同一个会话的记忆**，不同会话不串门。
- **失败必须静默**：服务没起、超时、没命中 → 安静跳过，绝不影响这一轮。记忆是加分项，不是单点故障。
- **只读不写**：这个插件不改你的记忆，只浮现。

---

## 它需要什么

- **DSH**（DeepSeek Harness），能加载第三方插件即可。
- 一个**本机的向量检索服务**，监听 8799，提供两个接口：
  - `GET /health` → 返回 200 即视为可用
  - `POST /recall`，body `{ "query": "...", "session": "...", "topK": 3, "min": 0.52 }`，
    返回数组 `[{ "title": "...", "text": "...", "at": 1767225600000, "cos": 0.61, "sess": "..." }, ...]`
    （包一层 `{ "hits": [...] }` 也认；插件发请求时两套键名都会带，你的服务认哪套都行）
- 一个中文向量模型（作者自用 `bge-small-zh`，CPU 就能跑，百来 MB）。

> 服务不在这个仓库里：不同人的记忆格式不一样，把它解耦出去，插件才能通用。
> 你只要让自己的 AI 按上面的接口契约写一个服务、指向你自己的记忆文件就行。

### 路径必须自己填（插件不猜）

插件里**没有任何写死的本机路径**。下面这些都可选，填了多一份能力，不填就少一点、但绝不报错：

| 你想要 | 填哪个 | 不填会怎样 |
|---|---|---|
| 服务没起时自动拉起来 | `daemon`（脚本完整路径；或 `home` + 默认脚本名） | 不自动起，只连 8799 上现成的那个 |
| 调试日志、会话↔账本映射 | `home`（你自己的 agents 目录） | 不写日志、不做会话映射，只用 `pool` 那本账 |
| 默认账本（无映射的会话查哪本） | `pool` | 只查本会话能匹配到的那本 |
| 换解释器 | `python` | 用 PATH 里的 `python` |

## 安装（让 AI 自己装）

这份 README 本来就是写给 AI 看的。把下面这段丢给你的 AI，它会自己完成：

```
把这个仓库装进我的 DSH：
1. 克隆 https://github.com/ac68z/dsh-memory-surface
2. 在 DSH 的 profile 里加依赖：dsh-memory-surface -> 指向克隆下来的目录
3. 在 profile 的 bundles 数组里加上 dsh-memory-surface
4. 帮我起一个本机向量检索服务（接口见 README），把你自己的记忆文件接上去，监听 8799
5. 重启 DSH，确认会话里能看到「记忆浮现」；把阈值调到不乱捞也不漏
```

再直白一点：**让 AI 自己去连自己的记忆库**。
不用你替它配路径、不用你手动导数据——它知道自己的记忆存在哪，让它自己接。

## 配置

两种给法：环境变量，或 `<DSH_HOME>/memory-surface.json`（这个文件的优先级更低，环境变量能盖它）。

| 环境变量 | JSON 键 | 默认 | 说明 |
| --- | --- | --- | --- |
| `DSH_MEMORY_SURFACE_PORT` | `port` | `8799` | 检索服务端口 |
| `DSH_MEMORY_SURFACE_MIN` | `min` | `0.52` | 命中阈值（余弦相似度） |
| `DSH_MEMORY_SURFACE_TOPK` | `topk` | `3` | 每轮最多浮现几条 |
| `DSH_MEMORY_SURFACE_HOME` | `home` | （空） | 你的 agents 目录：调试日志、会话映射都从这里走 |
| `DSH_MEMORY_SURFACE_DAEMON` | `daemon` | （空） | 检索服务脚本路径，填了才会自动拉起 |
| `DSH_MEMORY_SURFACE_PYTHON` | `python` | `python` | 起服务用的解释器 |
| `DSH_MEMORY_SURFACE_POOL` | `pool` | （空） | 无映射的会话默认查哪本账 |
| `DSH_MEMORY_SURFACE_CONFIG` | — | `<DSH_HOME>/memory-surface.json` | 换个配置文件位置 |

三层阈值（插件本地复核，和服务端对齐）：工程笔记 0.42、词典 0.58、记忆按上面的 `min`。

## 调参

| 现象 | 怎么做 |
| --- | --- |
| 浮出来的不相关 | 阈值上调到 0.55～0.6；先把明显重复的旧条目合并 |
| 该浮的没浮 | 先看服务在不在；太短的输入（「嗯」「好」）本来就不该命中 |
| 每轮都浮同一段 | 检查去重是否生效；多半是记忆本身重复了 |
| 会话里什么都没有 | 服务没起，或插件没挂在这个会话的预设上 |

**不要**改成「每轮全量注入」——那是每轮交一次记忆税，模型会被自己的旧账淹死。

---

## 边界

- 只读记忆，不写记忆、不改文件。
- 只在本会话内检索，不跨会话、不跨实例。
- 受限预设下不注入、不注册工具。
- 监听器全部异步 + try/catch，异常一律吞掉，绝不因为记忆插件报错把主流程带崩。

## 一句话

记忆的价值不在「我存了多少」，在「我想起来的那一条，正好是这一轮需要的」。
